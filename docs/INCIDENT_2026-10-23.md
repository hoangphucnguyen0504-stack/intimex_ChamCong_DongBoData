# Dashboard 503: retention incompatible with Cham_cong adapter

Production investigation confirmed that all 17 entities were imported and had no unmapped records. However, EmailLogs had retention_days=7 and AuditLogs had retention_days=30. The Cham_cong rows API intentionally rejects reads for retained entities with HTTP 409 RETENTION_REQUIRES_HISTORY because the adapter does not merge archived Sheets history. The backend translates this response to DATA_DONG_BO_NOT_READY (503). Dashboard reads EmailLogs.

Resolved through the admin API by setting retentionDays=0 for EmailLogs and AuditLogs, preserving headers, tab bindings and records. Both rows endpoints returned HTTP 200 afterward. The local Cham_cong dashboard compute function also completed against production DataDongBo using its backend configuration. The deployed authenticated dashboard route was not directly tested.

Keep these entities in MySQL until the Cham_cong adapter supports archived history. This disables automatic retention cleanup for these two entities and increases long-term MySQL storage. It does not restore records already archived.

Read-only diagnosis: `node scripts/diagnose-readiness.mjs`.

Repair preview: `node scripts/repair-cham-cong-retention.mjs`. Apply with `--apply`. Uses local .env credentials without printing them; changes only the retention settings for these two existing imported entities.
